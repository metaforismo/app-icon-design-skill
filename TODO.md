# App Icon Studio checklist

This is the working checklist for the 2.0 Icon Composer workflow. Checked items are implemented in the repository; unchecked runtime items must be completed for each real app icon and reported with evidence.

## Repository and skill

- [x] Reduce exploration to one precise direction or at most two distinct directions.
- [x] Generate complete icon concepts before creating isolated production parts.
- [x] Use stable version IDs and one-variable revisions.
- [x] Require explicit approval of a named version.
- [x] Apply the same approval gate to repository and skill branding.
- [x] Add a category-collision and small-size review before approval.
- [x] Add the Composer-feasibility gate after approval.
- [x] Require reapproval when a Composer adaptation changes a protected invariant.
- [x] Keep a clearly labeled flattened fallback for inseparable illustration.
- [x] Document Default, Dark, Mono, Clear, and Tinted appearance review.
- [x] Document the four-group limit and Individual versus Combined materials.
- [x] Add brief, concept-review, design-lock, layer-plan, and evidence templates.
- [x] Add deterministic size, appearance, and synthetic context-board QA.
- [x] Preserve third-party screenshots as private inspiration only.
- [x] Validate the repository, tests, canonical skill package, and four examples.
- [x] Rebuild the existing Quiet Tide `.icon` fixture with Xcode 26.6.
- [ ] Replace the current App Icon Studio identity only after a named replacement is explicitly approved.

## Per-icon creative gate

- [ ] Record the brief, target platforms, category neighbors, recognition anchor, and collision to avoid.
- [ ] Generate one complete direction for a precise brief or at most two when unresolved.
- [ ] Show each retained version full-size and at 32 px.
- [ ] Change one requested variable while preserving the recorded invariants.
- [ ] Record explicit approval, artifact path, SHA-256, date, and evidence note.

## Per-icon Composer gate

- [ ] Classify every effect as source geometry, intrinsic raster detail, or platform material.
- [ ] Decide whether the approved design can survive reconstruction in four or fewer semantic groups.
- [ ] If not, obtain approval for a named Composer-adapted concept or the flattened fallback.
- [ ] Reconstruct deliberate SVG/PNG sources on the complete Apple canvas.
- [ ] Recompose and compare the sources with the approved version at 1024 px and 32 px.
- [ ] Create and save the `.icon` with Apple Icon Composer; never fabricate its document structure.
- [ ] Review group order, Individual/Combined behavior, Effects, specular, refraction, blur, translucency, and shadow.
- [ ] Author Default, Dark, and Mono; inspect Clear and Tinted light/dark previews.
- [ ] Review every selected platform, mask, size, background, and lighting angle.

## Per-app delivery evidence

- [ ] Associate the tool-saved `.icon` with the intended Xcode target and App Icon build setting.
- [ ] Build the intended target with the supported Xcode toolchain.
- [ ] Observe the compiled icon in requested Simulator surfaces.
- [ ] Observe named physical devices and supported OS releases when available.
- [ ] Verify alternate icons and older-release behavior when in scope.
- [ ] Run the static QA CLI and retain its JSON report and preview assets.
- [ ] Record each result as **Validated**, **Prepared**, or **Not tested**.
- [ ] Treat App Review and Product Page Optimization as separate, unguaranteed outcomes.
